Builder

Creational · separate the construction of a complex object from its representation, so the same construction process can create different representations (GoF, 1994).

The cast

Minimal TypeScript skeleton

class Product { /* fields with sensible defaults */ }

interface Builder {
  reset(): this;
  stepA(x: string): this;   // every step returns `this` → chainable
  stepB(): this;
  build(): Product;         // only build() breaks the chain
}

class ConcreteBuilder implements Builder {
  private p = new Product();
  reset(): this { this.p = new Product(); return this; }
  stepA(x: string): this { /* mutate this.p */ return this; }
  stepB(): this { /* mutate this.p */ return this; }
  build(): Product { const done = this.p; this.reset(); return done; }
}

class Director {
  private builder: Builder;                 // NOT constructor(private builder: Builder)
  constructor(builder: Builder) { this.builder = builder; }
  makeStandardThing(): Product {
    return this.builder.reset().stepA('preset').stepB().build();
  }
}

Rules of thumb

  • Every step mutates the work-in-progress and returns this (the polymorphic this type) — that's the fluent API.
  • build() hands over the product, then resets — one builder instance serves many orders.
  • Recipes (fixed step sequences) belong in the director; one-off orders can drive the builder directly. The director is explicitly optional.
  • The director depends on the interface, never a concrete builder — swap builders to get different representations from the same recipe.

Reach for it when…

  • A constructor is telescoping: many parameters, most optional.
  • The same construction steps should yield different representations.
  • Construction is genuinely step-wise (assembled over time, validated at the end).

Skip it when…

  • An object literal with optional properties says it all: new Sandwich({ bread: 'rye', toasted: true }) — TypeScript's named/optional params cover many classic builder use-cases.
  • There's only one representation and construction is one shot — plain constructor wins.

Node gotcha (type stripping)

  • node file.ts erases types but does not transform code: no enum, no constructor parameter properties (constructor(private x: T)). Declare fields, assign in the body.
